# Tiny Distillation Contamination Audit Pilot

This repository is a **tiny-scale pilot/protocol study** for distillation-data leakage and contamination auditing. It focuses on a practical question: if we intentionally control overlap between distillation training data and evaluation items at tiny scale, can simple signals (exact overlap and n-gram similarity) separate clean vs contaminated settings? The goal is not to claim a universal detector for all reasoning models; it is to provide a reproducible micro-benchmark that tests whether contamination signals are visible and fragile in a controlled setup.

## Audit conditions

The workflow creates three controlled training conditions from the same base tiny train set and tiny eval set:

1. **clean**: 0% direct eval overlap injected into train.
2. **partial_overlap**: ~33% of eval examples injected into train.
3. **high_overlap**: ~83% of eval examples injected into train.

Condition files are generated by `scripts/make_overlap_conditions.py` into `outputs/conditions/`.

## Detection or audit method

The audit stage (`scripts/contamination_audit.py`, orchestrated by `scripts/eval_contamination.py`) computes:

- **Exact overlap rate**: fraction of eval questions appearing verbatim in train.
- **Average max 3-gram Jaccard**: for each eval question, compute the best 3-gram Jaccard similarity against any train question, then average.
- **Near-duplicate rate**: fraction of eval questions whose best 3-gram Jaccard is above 0.8.

A tiny optional proxy-student adaptation is included (`scripts/train_tiny_distill.py`), implemented as a QA memorizer. This keeps runtime very small while showing how contamination can inflate evaluation metrics.

## Predicted results based on prior literature

Based on prior contamination and memorization discussions in the literature, this pilot predicts:

- clean condition should show low exact overlap and lower near-duplicate signals,
- partial overlap should show intermediate signals,
- high overlap should show strongest overlap signals,
- proxy-student accuracy should rise with overlap when eval questions are copied into train.

These are directional expectations only in a tiny synthetic setup.

## Limitations

- Tiny synthetic data; not representative of broad real-world model behavior.
- Simple lexical metrics (exact match + 3-gram Jaccard) can miss semantic contamination and can over-flag templated data.
- Proxy student is a memorizer, not a modern reasoning model.
- Results depend on dataset construction and threshold choices.
- This repository does **not** prove universal contamination detection.

## What this study proves and does not prove

### What it can show
- A fully reproducible, self-contained protocol for generating clean and contaminated conditions.
- Whether simple contamination signals separate those conditions at tiny scale.
- How sensitive that separation is to overlap amount.

### What it cannot show
- A definitive detector for all models or all data pipelines.
- Causal claims about real production systems without larger, independent studies.
- Robustness against adversarial paraphrase or sophisticated leakage channels.

## Local run

```bash
python scripts/make_overlap_conditions.py
python scripts/eval_contamination.py
```

Metrics are written to:

- `outputs/metrics/clean.json`
- `outputs/metrics/partial_overlap.json`
- `outputs/metrics/high_overlap.json`
- `outputs/metrics/aggregate_summary.json`

## GitHub Actions

Workflow: `.github/workflows/contamination-audit.yml`

It:
1. installs Python,
2. builds overlap conditions,
3. runs the audit + tiny proxy evaluation,
4. uploads JSON metrics as an artifact.
